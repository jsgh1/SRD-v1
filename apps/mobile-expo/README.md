# SRD en Expo Go (demostración Android)

Este proyecto presenta en Expo Go las pantallas móviles ya construidas para SRD: acceso con junta y MFA, resumen, consulta y alta pendiente de personas, agenda e invitaciones, avisos y preferencias, perfil y cambio de junta. El inicio muestra indicadores, tarjetas de acceso y navegación inferior para Inicio, Personas, Agenda, Avisos y Perfil. Al volver al inicio se actualizan los indicadores; el botón Atrás de Android regresa desde las pantallas internas y conserva el bloqueo cuando hay un cambio de junta sin confirmar. El código se adaptó desde `apps/mobile`; la app Android nativa original permanece en esa carpeta. Esta variante **no es un APK final**. El 8 de octubre de 2026 se probó en un Android físico por USB.

## Preparar la demostración por USB

Para levantar la demostración web y móvil con una sola orden, consulta `../../docs/GUIA-EXPOSICION-2026-10-09.md` y ejecuta `./scripts/Start-Exposition.ps1` desde la raíz. Los pasos separados siguientes sirven para iniciar o revisar cada parte por separado.

Necesitas un teléfono Android con **Expo Go compatible con SDK 57** instalado, depuración USB habilitada y autorizada para esta PC. Si la app indica incompatibilidad de versión, instala en el teléfono la versión de SDK 57 desde [expo.dev/go](https://expo.dev/go). El servidor SRD corre solo en `localhost`; el reenvío de ADB permite que el teléfono acceda por USB sin abrir puertos de la red ni usar túneles externos. Mantén el teléfono conectado.

1. En PowerShell, desde la raíz `SRD`, arranca Docker Desktop y ejecuta `./scripts/Prepare-ExpoDemo.ps1`. Inicia solo los servicios necesarios para estas pantallas móviles, Mailpit y el acceso web local. Si faltan imágenes, ejecuta `./scripts/Prepare-ExpoDemo.ps1 -Build`. Espera hasta que `http://localhost:8080` responda. Para una demo de **toda la web**, usa `./scripts/Prepare-Demo.ps1 -SkipBuild` en su lugar; consume más memoria.
2. En otra terminal, desde `SRD`, ejecuta `./scripts/Start-ExpoGo.ps1`. El script comprueba que haya un solo teléfono autorizado, ejecuta `adb reverse` para los puertos 8080 y 8081, inicia Metro en modo local y abre Expo Go. Si `adb.exe` está en otra ubicación, pasa `-AdbPath 'RUTA\adb.exe'`. Mantén esta terminal abierta.
3. Si Expo Go no se abre automáticamente, ábrelo en el teléfono y usa `exp://127.0.0.1:8081`. También puedes ejecutar `adb shell am start -a android.intent.action.VIEW -d exp://127.0.0.1:8081` desde otra terminal, con la ruta completa de `adb.exe` si no está en `PATH`.
4. En la app, usa servidor `http://localhost:8080` y código de junta `srd-e2e-a`. La cuenta sintética es `admin@srd-e2e.test`; su contraseña está en el campo `password` de `.local/e2e-fixture.json`. La semilla comparte esa clave entre sus seis cuentas ficticias. El código de seis dígitos llega solo a Mailpit local: `http://localhost:8025` en la PC. No compartas ese archivo ni códigos reales.

Para poblar la junta de prueba con ocho personas pendientes, cuatro eventos, tres movimientos de tesorería y tres bienes ficticios, ejecuta `./scripts/Seed-Exposition.ps1` después de preparar Docker. Requiere las dependencias de pruebas instaladas con `npm ci` en `tools/browser-tests`; consulta Mailpit local para completar MFA y evita duplicar los registros. Es una semilla exclusiva de la junta de prueba. Si la API responde 429 tras varios accesos seguidos, espera a que termine el límite temporal antes de repetirla.

Para una demostración corta, inicia sesión, muestra los cuatro indicadores y abre Personas, Agenda, Avisos y Perfil desde la barra inferior. Puedes crear una **persona totalmente ficticia** desde «Registrar persona», usando un número de documento inventado y nuevo en cada ensayo, y dejarla «Pendiente»; al volver a Inicio se consultan de nuevo los indicadores. Usa únicamente datos de prueba y explica que completar la ficha y adjuntar fotografías sigue siendo una tarea pendiente del móvil.

Para reinstalar dependencias en otra PC: dentro de `apps/mobile-expo`, ejecuta `npm ci`. En el equipo de desarrollo se probó con Expo SDK 57, React Native 0.86.3 y Node 24. La primera instalación de Expo Go y `npm ci` requieren descargarse en esa PC; **el script ejecuta Metro con `EXPO_OFFLINE=1` y no usa túnel**.

La conexión guardada contiene únicamente la dirección del servidor y el código de junta mediante `expo-secure-store`. Las credenciales, códigos MFA y cookies no se guardan en esa preferencia. La sesión depende de las cookies y CSRF del gateway. En el teléfono de prueba persistió al salir y reabrir Expo Go; falta comprobar la revocación y caducidad en un dispositivo físico.

## Alcance actual

TypeScript, lint y el bundle Android de Expo pasan. Se exportó además una vista web **solo para revisión visual**: un recorrido con respuestas sintéticas completó junta, login, MFA, resumen, navegación por Personas, Agenda, Perfil y Avisos a 320 px, y verificó que volver a Inicio vuelve a solicitar los indicadores. Un recorrido separado contra el backend real (`tools/browser-tests/mobile-expo-api.spec.mjs`) aprobó junta, login, código MFA de Mailpit, `/me`, resumen, personas, agenda, avisos y cierre de sesión con las cuentas ficticias. En un Android físico se comprobó conexión USB con `adb reverse`, login y MFA reales, Inicio, tres personas ficticias, dos eventos en Agenda, apertura de Avisos y Perfil, y persistencia de la sesión al reabrir Expo Go. Siguen pendientes el botón Atrás, revocación/caducidad, escrituras de persona y perfil desde ese teléfono y recorridos con avisos o invitaciones reales. No incluye chat, llamadas, edición completa de personas, subida de fotos, notificaciones push ni selector ES/EN. Expo Go sirve para mostrar y probar este avance; una app distribuible necesitará compilación y pruebas propias. La web tiene pendientes separados documentados en `docs/WEB_ACEPTACION.md`.
