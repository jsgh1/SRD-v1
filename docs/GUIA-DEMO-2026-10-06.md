# Guía para levantar, explicar y demostrar SRD

**Corte: 6 de octubre de 2026.** Esta guía acompaña el [informe de avance y pendientes](AVANCE-PARA-EXPOSICION-2026-10-06.md). SRD es un prototipo avanzado para trabajar con varias Juntas de Acción Comunal sin mezclar sus datos. La demostración principal es la **web local**; Android y Windows son clientes adicionales en desarrollo.

## Qué contiene el ZIP de exposición

Al extraer `SRD-exposicion-2026-10-06.zip` aparece una carpeta `SRD/` con el código y estos archivos:

| Ruta | Función |
| --- | --- |
| `apps/web/` | Interfaz React del navegador. |
| `apps/mobile/` | Cliente Android React Native. |
| `apps/desktop/` | Ventana Windows Electron que carga la web de SRD. |
| `services/gateway/` | Entrada pública de la API, sesión, CSRF y contexto de junta. |
| `services/identity/`, `configuration/`, `records/` | Acceso/roles; juntas/términos; personas. |
| `services/audit/`, `files/`, `calendar/`, `notifications/` | Bitácora; archivos privados; eventos; avisos. |
| `services/treasury/`, `inventory/`, `chat/` | Libro informativo; bienes; conversaciones. |
| `packages/php/`, `contracts/` | Código compartido y contratos de API/eventos. |
| `docker/`, `compose.yaml`, `scripts/` | Construcción, arranque, datos ficticios y pruebas locales. |
| `docs/` | Alcance, arquitectura, trazabilidad, evidencia y esta guía. |
| `entregables/` | APK debug para **emulador x86_64** e instalador Windows **sin firma**, si estuvieron disponibles al crear el paquete. Son opcionales para la demo web. |

El paquete **no incluye datos ni contraseñas**, `.env`, `.local`, `node_modules`, `vendor` o imágenes Docker. La primera instalación construye/descarga dependencias y puede tardar. El instalador Windows necesita el servidor SRD encendido; el APK no es una versión para un teléfono ARM de uso general.

## Preparar otra PC Windows

1. Instala **Docker Desktop con contenedores Linux** y **Node.js 24**. Usa PowerShell. Habilita virtualización/WSL2 según las indicaciones de Docker. Conviene tener al menos 16 GB de RAM y suficiente espacio para imágenes/volúmenes; cierra emuladores y aplicaciones pesadas durante el primer arranque.
2. Extrae el ZIP en una carpeta de trabajo. Abre PowerShell **dentro de la carpeta `SRD` extraída**, donde están `compose.yaml` y `README.md`.
3. Abre Docker Desktop y espera a que el motor indique que está activo. Ejecuta:

   ```powershell
   ./scripts/Prepare-Demo.ps1
   ```

   El script llama a `Up.ps1`, crea `.env` con secretos aleatorios **solo en esa PC**, construye/arranca los contenedores, aplica migraciones y siembra dos juntas y cuentas **ficticias**. No requiere instalar PHP ni MySQL globalmente. Si PowerShell bloquea scripts, usa una sesión temporal sin cambiar la política global: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Prepare-Demo.ps1`.
4. Abre `http://localhost:8080/j/srd-e2e-a/login`. La cuenta de prueba es `admin@srd-e2e.test`; el código de junta es `srd-e2e-a`. La contraseña aleatoria está en `.local/e2e-fixture.json`, campo `password`, creado **después** de la siembra. Puedes leerla en privado con `(Get-Content .local/e2e-fixture.json -Raw | ConvertFrom-Json).password`.
5. Acepta los términos ficticios e inicia sesión. El código de seis dígitos llega a **http://localhost:8025**, Mailpit local. Abre el mensaje más reciente para la cuenta usada y escribe el código en SRD. El correo no sale a un servidor externo.

Haz estos pasos **hoy**, antes de exponer: el primer arranque puede tardar y descargar imágenes. Con `docker compose ps` comprueba los contenedores; con `http://localhost:8080` comprueba la portada. No borres `.env` ni volúmenes para «reiniciar» una instalación existente: los secretos protegen los datos de esa instalación. Para detener sin borrar datos usa `./scripts/Down.ps1`; para volver a abrir, `./scripts/Up.ps1`. Si ya están construidas las imágenes, `./scripts/Up.ps1 -SkipBuild` acelera el arranque.

En la PC de desarrollo, `./scripts/Prepare-Demo.ps1 -SkipBuild` pasó el 6 de octubre: la web y Mailpit dieron HTTP 200 y la junta ficticia respondió por API. Esto verifica imágenes existentes; en una PC nueva usa el comando **sin** `-SkipBuild`. Con toda la pila activa la memoria libre de esta PC de 16 GB bajó aproximadamente a 1 GB, por lo que conviene preparar la demo con antelación y no abrir el emulador al mismo tiempo.

## Recorrido sugerido para el instructor

1. **Problema y diseño:** explica que una misma plataforma atiende varias juntas y que cada petición se autoriza con sesión, rol y junta. Muestra el login directo `/j/srd-e2e-a/login` y la aceptación de términos.
2. **Panel y registros:** después del MFA, abre el resumen, registra una persona **ficticia**, vuelve a Lista, busca por documento y abre la ficha. Muestra que los cargos y campos adicionales pueden configurarse para la junta. No uses datos de personas reales.
3. **Trabajo de la junta:** enseña Calendario, Tesorería e Inventario. Cada uno tiene pantallas y datos propios; Tesorería es un libro informativo, no una pasarela bancaria.
4. **Seguridad y trazabilidad:** muestra los roles desde Configuración, la bandeja de avisos y la vista Auditoría. Si una opción aparece vacía, explica que los datos ficticios recién creados aún no generaron ese tipo de evento.
5. **Otros clientes:** muestra el APK/instalador como evidencia de compilación. Android usa el gateway y todavía es parcial. Windows muestra la misma web en una ventana restringida. Para enseñar funciones completas, quédate en el navegador.
6. **Honestidad del alcance:** abre [AVANCE-PARA-EXPOSICION-2026-10-06.md](AVANCE-PARA-EXPOSICION-2026-10-06.md) y señala los cuatro RF pendientes completos y las pruebas de aceptación aún necesarias.

## Cómo funciona cada capa

```text
Navegador React / Electron / Android React Native
                    │
                    ▼
          Web local + Gateway Laravel
                    │ sesión, CSRF, junta, contexto firmado
                    ▼
       Servicios Laravel independientes
                    │ base MySQL propia por dominio
                    ▼
      Auditoría / trabajos / correo local
```

**Web** organiza formularios, listados y pantallas. **Electron** reutiliza esa web y necesita la dirección del servidor. **Android** tiene pantallas nativas propias y consume la API. **Gateway** resuelve la sesión y protege la entrada. **Identidad** controla cuentas, roles, MFA y sesiones. **Configuración** guarda juntas y términos. **Registros** guarda fichas de personas. **Archivos** valida y conserva objetos privados. **Calendario, Notificaciones, Tesorería, Inventario y Chat** manejan sus temas sin compartir tablas. **Auditoría** recibe eventos mínimos mediante trabajos reintentables. MySQL y Mailpit funcionan en contenedores locales durante la demo.

## Si algo no abre

- **Docker no responde:** abre Docker Desktop, espera el motor Linux y repite `./scripts/Prepare-Demo.ps1`. No abras el emulador Android a la vez en una PC con 16 GB de RAM.
- **La web tarda o muestra error inicial:** revisa `docker compose ps`; espera a que los servicios pasen sus comprobaciones de salud. Repite `./scripts/Up.ps1 -SkipBuild` si hubo un reinicio del equipo.
- **No llegó el código:** revisa Mailpit en `http://localhost:8025` y la dirección de la cuenta. El segundo factor sigue siendo obligatorio.
- **La contraseña no funciona:** lee el `password` del fixture **de esa PC**. La siembra es idempotente y no sustituye contraseñas ya existentes.
- **Falta espacio o memoria:** detén aplicaciones pesadas; para la exposición web no se necesita emulador, Metro ni Android Studio.

## Límites de esta entrega

El ZIP es una **instantánea reproducible de desarrollo**, no un servicio publicado ni un instalador oficial. El primer arranque requiere Docker/Node y acceso a dependencias públicas. No incluye datos anteriores de la PC de desarrollo. La evidencia histórica detallada está en [VALIDACION.md](VALIDACION.md) y el estado por requisito en [TRAZABILIDAD.md](TRAZABILIDAD.md).
